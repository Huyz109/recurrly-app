# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run start` — start the Expo dev server (Metro). Use `npm run ios` / `npm run android` / `npm run web` to launch directly into a target.
- `npm run lint` — runs `expo lint` (ESLint flat config extending `eslint-config-expo/flat`).
- `npm run reset-project` — destructive: moves or deletes `app/`, `components/`, `hooks/`, `constants/`, `scripts/` and scaffolds a blank `app/`. Don't run unless the user explicitly asks; the project is past the starter stage.

There is no test runner configured.

## Stack & build configuration

- **Expo SDK 54** with the **New Architecture** enabled (`app.json` → `newArchEnabled: true`) and the **React Compiler** experiment on (`experiments.reactCompiler: true`). React 19.
- **expo-router v6** with **typed routes** (`experiments.typedRoutes: true`). Route types are generated under `.expo/types/`. After adding/renaming routes you may need to restart the dev server for typed-route inference to refresh.
- **NativeWind v5 preview** + **Tailwind CSS v4** via `@tailwindcss/postcss`. Metro is wrapped with `withNativewind` in `metro.config.js`. `lightningcss` is pinned to `1.30.1` via `overrides` in `package.json` — don't bump it without checking NativeWind/Tailwind v4 compatibility.
- TypeScript is `strict`; the path alias `@/*` maps to the repo root (`tsconfig.json`).

## Architecture

### Routing layout (`app/`)

File-based routing via expo-router. The structure is:

- [app/_layout.tsx](app/_layout.tsx) — root `Stack`, headers hidden globally. Imports `@/global.css` here so Tailwind styles are loaded once for the whole app.
- [app/(tabs)/](app/(tabs)/) — bottom-tabs group. Tabs are **data-driven**: [app/(tabs)/_layout.tsx](app/(tabs)/_layout.tsx) iterates over `tabs` from [constants/data.ts](constants/data.ts) to render `<Tabs.Screen>` entries. To add a tab, create the screen file in `app/(tabs)/` AND add an entry to `constants/data.ts` (icon must exist in [constants/icons.ts](constants/icons.ts)).
- [app/(auth)/](app/(auth)/) — auth flow group (`sign-in`, `sign-up`).
- [app/subscriptions/[id].tsx](app/subscriptions/[id].tsx) — dynamic subscription detail route. Linked to via typed-routes, e.g. `href={{ pathname: "/subscriptions/[id]", params: { id: "claude" } }}`.
- [app/onboarding.tsx](app/onboarding.tsx) — top-level onboarding screen.

### Theming — keep two sources in sync

Design tokens are duplicated in two places and **must be kept consistent**:

1. [global.css](global.css) — CSS custom properties under `@theme { … }` (consumed by Tailwind utilities like `bg-background`, `text-accent`, `--spacing-*`).
2. [constants/theme.ts](constants/theme.ts) — the same colors/spacing as TS constants (used by inline `StyleSheet`/`style={…}` props where Tailwind classes can't reach, e.g. the tab bar styling in `(tabs)/_layout.tsx`).

If you add or change a token, update both files. `global.css` also defines reusable component classes via `@layer components` (e.g. `.tabs-icon`, `.tabs-pill`, `.tabs-active`, `.tabs-glyph`) — prefer these over re-declaring the same Tailwind chains.

### Type declarations

- [type.d.ts](type.d.ts) — global ambient types (e.g. `TabIconProps`). Add cross-cutting prop types here rather than re-declaring locally.
- [image.d.ts](image.d.ts) — declares `*.png` / `*.jpg` / `*.svg` etc. as modules so static image imports type-check.
- [nativewind-env.d.ts](nativewind-env.d.ts) — **auto-generated by react-native-css; do not edit**.

### Static assets

Image assets are imported as ES modules and re-exported from a central registry:
- Icons: [constants/icons.ts](constants/icons.ts) (`icons.home`, `icons.spotify`, …) with a derived `IconKey` union.
- Tab metadata: [constants/data.ts](constants/data.ts).

When adding an icon, drop the PNG into `assets/icons/`, import it in `constants/icons.ts`, and reference it via the `icons` map — don't import asset paths directly from screens.
